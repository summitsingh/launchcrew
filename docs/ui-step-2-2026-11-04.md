# UI work order, Step 2

Implemented by Codex on Nov 4, 2026. Scope: design system and app shell only. This report describes source changes, not deployed or browser-verified behavior.

## Delivered

- Extended the existing Tailwind 4 and shadcn setup with command, checkbox, switch, avatar, breadcrumb, and scroll-area. Components were added through shadcn CLI 4.23.0 using official sources supplied as offline registry items because shell DNS was unavailable. MIT attribution is in `web/SHADCN-LICENSE.txt`.
- Added neutral light and dark tokens, light-default theme initialization, Geist Sans, and Geist Mono. Existing Button and Classic component patterns remain available.
- Added the shared presentation mapping in `web/src/lib/ui-status.ts`: launch statuses, claim verdicts, known API reasons, and a neutral unknown state. Labels never grant approval or publishing permission. Command results and the Needs review count use this mapping. Classic screen internals retain their existing mappings until the screen migration steps.
- Added the sticky shadcn sidebar, mobile Sheet navigation, breadcrumbs, a skip link, and Cmd+K or Ctrl+K command search. Search opens screens and existing launches. Sidebar totals and search use the same queue response as the adapted queue body, with no archive/test classification guesses.
- Added an avatar-only account menu and Sign out for authenticated mode. Its theme action supports menu keyboard navigation. Public demo mode has no account menu or sign-out action. No identity banner, display name, email, or provider subject is added to the shell.
- Added runtime server flag `LAUNCHCREW_NEW_UI`, default on. `false`, `0`, and `off` select Classic. The root layout is dynamic so the flag is read at request time. `/classic` bypasses the shell even with the flag enabled.
- Updated README authorship to credit Codex's UI contribution truthfully.
